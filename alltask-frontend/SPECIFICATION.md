# AllTask Todo フロントエンド仕様書

## 1. 概要

AllTask Todo は、カテゴリ単位でタスクを管理する React 製 Todo アプリケーションである。
ユーザーはカテゴリを作成し、カテゴリ配下にタスクを登録、編集、削除、完了管理できる。
また、期限付きタスク、日課タスク、フラグ付きタスクを専用ビューで確認できる。

本仕様は、現在のフロントエンド実装から読み取れる内容を基に作成している。

## 2. 技術構成

- フレームワーク: React 19
- 言語: TypeScript
- ビルドツール: Vite
- スタイリング: Tailwind CSS
- HTTP クライアント: Axios
- API ベース URL: `http://localhost:8080`
- 開発サーバー: Vite 標準の `npm run dev`
- Docker 実行時ポート: `5173`

## 3. 画面構成

### 3.1 共通レイアウト

- 全画面にヘッダーを表示する。
- ヘッダーにはアプリ名 `AllTask Todo` を表示する。
- アプリ名をクリックするとトップ画面へ戻る。
- カテゴリ取得中は `読み込み中...` を表示する。

### 3.2 トップ画面

トップ画面では以下を表示する。

- `日付あり` ボタン
- `日課` ボタン
- `フラグ` ボタン
- カテゴリ一覧
- `カテゴリの編集` ボタン
- `新しいタスクを追加` ボタン

各ボタンの遷移先は以下とする。

| 操作 | 遷移先 |
| --- | --- |
| 日付あり | 日付ありタスク一覧 |
| 日課 | 日課タスク一覧 |
| フラグ | フラグ付きタスク一覧 |
| カテゴリカード | 選択カテゴリのタスク一覧 |
| カテゴリの編集 | カテゴリ編集モーダル |
| 新しいタスクを追加 | 新規タスク作成モーダル |

### 3.3 タスク一覧画面

タスク一覧画面は以下のビューを持つ。

| ビュー | 表示条件 |
| --- | --- |
| カテゴリ詳細 | 選択カテゴリ ID と一致するタスク |
| 日付ありタスク | 期限日が設定されているタスク |
| 日課タスク | `daily` が `true` のタスク |
| フラグ付き | `hasFlag` が `true` のタスク |

一覧画面では以下を行える。

- 戻るボタンでトップ画面へ戻る。
- 完了済みタスクの表示、非表示を切り替える。
- タスクの完了状態をチェックボックスで切り替える。
- タスクカードをクリックして詳細編集モーダルを開く。
- ゴミ箱ボタンでタスクを削除する。
- ドラッグアンドドロップでタスクの表示順を変更する。

タスク一覧の表示順は、完了状態で並び替えず、手動並び順または選択中の並び替え条件を維持する。

## 4. タスク仕様

### 4.1 タスク項目

| 項目 | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | number | はい | タスク ID |
| `categoryId` | number \| null | はい | 所属カテゴリ ID |
| `title` | string | はい | タスクタイトル |
| `status` | `INCOMPLETE` \| `DONE` | はい | 完了状態 |
| `details` | string \| null | いいえ | 詳細メモ |
| `dueDate` | string \| null | いいえ | 期限日。形式は `YYYY-MM-DD` |
| `daily` | boolean | はい | 日課タスクかどうか |
| `hasFlag` | boolean | はい | フラグ付きタスクかどうか |
| `autoCarryOver` | boolean | はい | 自動繰り越し設定 |
| `overdueBehavior` | number | はい | 期限超過時の挙動 |
| `sortOrder` | number \| null | いいえ | 並び順 |

### 4.2 新規タスク作成

新規タスク作成モーダルでは以下を入力できる。

- タイトル
- カテゴリ
- 期限日
- 期限超過時の動き
- 詳細メモ
- 重要フラグ
- 日課フラグ

作成時のバリデーションは以下とする。

- タイトルが空の場合は作成できない。
- カテゴリが未選択の場合は作成できない。
- カテゴリ詳細画面から作成する場合は、現在表示中のカテゴリを自動的に使用する。
- トップ画面から作成する場合は、ユーザーがカテゴリを選択する必要がある。
- 作成時の初期ステータスは `INCOMPLETE` とする。

期限日と日課の関係は以下とする。

- 期限日を設定した場合、日課は `false` になる。
- 日課を有効にした場合、期限日は空になる。
- 期限日がない場合、期限超過時の動きは `0` になる。

### 4.3 タスク詳細編集

タスクカードをクリックすると詳細編集モーダルを開く。
詳細編集モーダルでは以下を編集できる。

- 完了状態
- タイトル
- 重要フラグ
- カテゴリ
- 日課フラグ
- 期限日
- 期限超過時の動き
- 詳細メモ

変更がある場合は `キャンセル` と `保存` を表示する。
変更がない場合は `閉じる` と `削除` を表示する。

保存時のバリデーションは以下とする。

- タイトルが空の場合は保存できない。
- カテゴリが未選択の場合は保存できない。

編集後のタスクが現在のビュー条件に合わなくなった場合、そのタスクは現在の一覧から除外する。

### 4.4 完了状態

- 未完了タスクのステータスは `INCOMPLETE` とする。
- 完了済みタスクのステータスは `DONE` とする。
- 一覧のチェックボックス操作で `INCOMPLETE` と `DONE` を相互に切り替える。
- 完了済みタスクは一覧上で薄く表示し、タイトルに取り消し線を付ける。

### 4.5 期限表示

- 期限日があるタスクは期限日バッジを表示する。
- 今日より過去の期限日で、かつ未完了のタスクは期限超過として赤系の表示にする。
- 期限超過判定はフロントエンドの現在日付を `YYYY-MM-DD` 形式で比較する。

### 4.6 期限超過時の動き

期限日が設定され、日課ではないタスクに対して以下を選択できる。

| 値 | 表示名 |
| --- | --- |
| `0` | 日付を赤文字でそのまま |
| `1` | 日付を今日に繰り越す |
| `2` | 自動的に完了済みにする |
| `3` | 日付を削除する |

実際の期限超過処理はフロントエンドでは実行しておらず、値の保存と表示のみを行う。

## 5. カテゴリ仕様

### 5.1 カテゴリ項目

| 項目 | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | number | はい | カテゴリ ID |
| `name` | string | はい | カテゴリ名 |

### 5.2 カテゴリ一覧

- トップ画面にカテゴリカードをグリッド表示する。
- カテゴリカードにはカテゴリ名と、カテゴリ名の先頭 1 文字を表示する。
- カテゴリカードをクリックすると、そのカテゴリのタスク一覧へ遷移する。

### 5.3 カテゴリ編集

カテゴリ編集モーダルでは以下を行える。

- カテゴリ追加
- カテゴリ名編集
- カテゴリ削除

カテゴリ名編集の仕様は以下とする。

- メニューの `編集` から編集モードに入る。
- Enter キーで保存する。
- Escape キーで編集をキャンセルする。
- `保存` ボタンでも保存できる。
- `キャンセル` ボタンで編集をキャンセルできる。
- 空のカテゴリ名は保存できない。

カテゴリ削除の仕様は以下とする。

- メニューの `削除` から削除する。
- 削除前に確認ダイアログを表示する。
- 確認文では、カテゴリ内のタスクもすべて削除されることを表示する。
- 削除成功後、カテゴリ一覧から対象カテゴリを除外する。

## 6. API 仕様

### 6.1 カテゴリ API

| 操作 | メソッド | パス | 説明 |
| --- | --- | --- | --- |
| 一覧取得 | GET | `/categories` | カテゴリ一覧を取得する |
| 作成 | POST | `/categories` | カテゴリを作成する |
| 更新 | PUT | `/categories/{id}` | カテゴリ名を更新する |
| 削除 | DELETE | `/categories/{id}` | カテゴリを削除する |

カテゴリ作成、更新のリクエスト例:

```json
{
  "name": "仕事"
}
```

### 6.2 タスク API

| 操作 | メソッド | パス | 説明 |
| --- | --- | --- | --- |
| 一覧取得 | GET | `/todos` | 条件に一致するタスク一覧を取得する |
| 作成 | POST | `/todos` | タスクを作成する |
| 更新 | PUT | `/todos/{id}` | タスク全体を更新する |
| ステータス更新 | PATCH | `/todos/{id}/status` | 完了状態を更新する |
| 並び順更新 | PATCH | `/todos/sort-order` | 複数タスクの並び順を更新する |
| 削除 | DELETE | `/todos/{id}` | タスクを削除する |

一覧取得時のクエリパラメータ:

| パラメータ | 型 | 説明 |
| --- | --- | --- |
| `categoryId` | number \| null | 指定カテゴリのタスクを取得する |
| `existsDueDate` | boolean | 期限日が存在するタスクを取得する |
| `daily` | boolean | 日課タスクを取得する |
| `hasFlag` | boolean | フラグ付きタスクを取得する |

ステータス更新のリクエストボディは JSON 文字列として送信する。

```json
"DONE"
```

並び順更新のリクエスト例:

```json
[
  {
    "id": 1,
    "sortOrder": 1
  },
  {
    "id": 2,
    "sortOrder": 2
  }
]
```

## 7. 状態管理

フロントエンドは React Hooks で状態を管理する。

| Hook | 役割 |
| --- | --- |
| `useViewMode` | 現在の表示モードと選択カテゴリを管理する |
| `useCategories` | カテゴリ一覧、カテゴリ作成、編集、削除を管理する |
| `useTodos` | タスク一覧、作成、編集、削除、完了切替、並び替えを管理する |
| `useTodoModal` | 新規タスク作成モーダルの開閉を管理する |
| `useCategoryModal` | カテゴリ編集モーダルの開閉と入力値を管理する |
| `useSelectedTodoModal` | タスク詳細モーダルの対象タスクを管理する |

## 8. エラー処理

- API 取得や更新に失敗した場合、主に `console.error` にエラーを出力する。
- 一部の操作では `alert` でユーザーに失敗を通知する。
- タスク削除は API 実行前に一覧から対象タスクを除外する。
- タスク削除 API が失敗した場合、現在の実装では自動復元しない。
- タスク並び順更新が失敗した場合、再取得用のキーを更新して一覧を再取得する。

## 9. 実行方法

依存関係をインストールする。

```bash
npm install
```

開発サーバーを起動する。

```bash
npm run dev
```

ビルドする。

```bash
npm run build
```

Lint を実行する。

```bash
npm run lint
```

Docker で起動する場合は、コンテナ内で Vite 開発サーバーを `--host` 付きで起動する。

- バックエンド API の詳細なレスポンス仕様や DB 制約は、このフロントエンド実装からは確認できない。
